# Ablation study results — 2026-08-02

Raw data: [`ablation_2026-08-02.json`](ablation_2026-08-02.json) — the exact output of
`python -m argus.eval.ablation` (see [`argus/eval/ablation.py`](../../argus/eval/ablation.py)),
committed verbatim. Six live runs against the real Gemini API: 3 pipeline variants ×
2 scenarios.

**Methodology note, stated plainly:** `groundedness` is emitted directly by the script — it's
`meta.groundedness`, the Verifier's own deterministic `check_grounding` score (not an LLM judging
itself; see `argus/tools/claim_matcher.py`). The **"Derived metrics" and "Unverified flags" columns
below are a manual read of the committed thesis text**, not something the script computes or
outputs automatically. Anyone can re-derive them independently from the raw JSON linked above.

## Summary

| Variant | Scenario | Groundedness | Unverified flags | Derived metrics present |
|---|---|---|---|---|
| baseline | Acme Corp (clean) | 1.0 | 0 | CAGR, YoY growth, margin trend, volatility |
| baseline | Globex (contradiction) | 1.0 | 0 | CAGR, YoY growth, margin trend, volatility |
| no_critic | Acme Corp (clean) | 1.0 | 0 | Same 4, YoY broken out per-year (more granular) |

| no_code_exec | Globex (contradiction) | 1.0 | 0 | **None** — only raw filed figures |

"Derived metrics" = any computed percentage (CAGR, YoY growth rate, margin, volatility) stated in
the thesis. Verified by searching each committed thesis for `%`: both `no_code_exec` runs contain
zero percentage-based claims outside of one literal fact restated from the source news data ("an 8%
workforce reduction" — a fact from `data/globex/news.json`, not a computed metric).

## What this shows

Removing the critic/refiner loop (`no_critic`) cost a small amount of groundedness specifically on
the harder scenario (1.0 → 0.9655, one flagged claim) and no analytical richness — its Acme response
is, if anything, more granular than baseline's.

Removing code execution (`no_code_exec`) did **not** lower groundedness at all (1.0 in both
scenarios) — `synthesis_agent`'s instruction to say "the analysis doesn't cover it" rather than
invent a number held under live testing. But it removed **100% of derived analytical content**: no
CAGR, no margin trend, no YoY growth rate, no volatility, in either scenario. The response is
accurate but shallow — it can only restate what's literally in the filings, not what they imply.

## Reproducing this

```bash
PYTHONPATH="$(pwd)" .venv/Scripts/python.exe -m argus.eval.ablation
```

Progress checkpoints to `.ablation_checkpoint.json` at the repo root (git-ignored, since it's a
resumable working file) so a rate-limit hit mid-run resumes instead of restarting. This file is a
snapshot of that checkpoint taken after a complete, successful run.
